midpro Nav2 이식 — 시뮬레이션 단계 복합 이슈 분석과 개선

2026-10-16 · 원본 ROS1 코드(loas_local_planner / loas_controller / loas_costmap / obstacle_detector 계열)와 ROS2 이식본(midpro_nav2_ws v0.69)을 대조한 분석

1. 원본 설계의 핵심 (무엇을 지켜야 했나)

요소원본(ROS1) 설계이식에서 바뀐 점
로컬 경로 상태기계straight → (NEAR만) line / (막힘) side_front → front_side → eband. side 지점은 "거기서 목표가 정면(±5°)에 오는 점", front 지점은 "거기서 목표가 90°에 오는 점" → 본질적으로 직각 주행. 복귀 후 try_side_로 재진입 억제상태기계는 유지. 단 홀로노믹 추종 법칙이 바뀌면서(아래) 두 구간을 대각선으로 잘라 가게 됨 → v0.41에서 side/front 분기 자체를 꺼 버림
제어 법칙holonomic: 바로 다음 점(path[1], 5 cm)을 향해 vx·vy, 속도는 pre-goal(구간 끝)까지 거리에 비례 → 모서리에서 자연 감속. ackermann: P 조향 + cos 결합 감속, 60° 초과면 제자리 회전. 횡속도 0.1 m/s 상한 + LPF격자 경로 떨림을 줄이려 0.4 m 앞 기준점 추종으로 통일(v0.10) → 홀로노믹 경로에서 모서리를 질러감(핵심 원인)
costmap라이다 점 마킹 + 2 s TTL 소멸(레이트레이싱 없음), inscribed 99 / NEAR 95 밴드(외접+0.1 m)Nav2 costmap(레이트레이싱 클리어). 무반사 광선 처리 누락으로 유령 셀 → v0.40 inf_is_valid
안전 계층obstacle_detector: 장애물 방향의 움직임만 차단(x±/y±/회전)Nav2 collision_monitor(방향 무관 전체 정지) → v0.66 midpro_safety로 복원·보완

2. 시뮬레이션에서 드러난 복합 이슈와 근본 원인

한 가지 현상에 여러 원인이 겹친 경우가 많았다. 현상 → 원인 → 원본 설계와의 관계 → 조치 순으로 정리한다.

현상근본 원인원본과의 관계조치
회피 중 대각선 크랩 후 끼임홀로노믹 경로를 0.4 m 기준점으로 추종 → 옆 구간과 직진 구간의 모서리를 대각선으로 절단. 긴 차체(0.9 m)가 비스듬히 구조물 사이로 진입원본은 path[1] 추종 + pre-goal 감속이라 직각으로 움직였음. 이식 과정의 퇴행v0.41 임시 차단 → v0.68 직각 회피, v0.69 홀로노믹 next-point 복원
옆이 가까우면 전진도 정지collision_monitor가 정지 영역 내 점 하나로 모든 축 정지. 컨트롤러 판정도 "옆이 가깝다"를 "끼였다"로 해석원본 obstacle_detector의 방향별 차단 개념이 빠져 있었음v0.66 obstacle_guard(방향별 닿기 거리·회전 스윕)
좁은 통로에서 출렁임·멈칫격자 글로벌 경로의 중앙선이 통로 폭 변화마다 이동 → S자 → 조향·필터·접근제동 연쇄 반응원본은 straight/line이 "직선"이라 통로에선 곧게 감v0.61·v0.65 경로 당겨 펴기(6→3→1 cm)
직진 중 조향 ±0.05 진동min_angular_vel 하한이 주행 중 미세 보정(0.01)을 0.05로 부풀려 리밋 사이클원본에도 같은 하한이 있었으나 0.2 m/s 저속·느슨한 추종에서 드러나지 않음v0.46 제자리 회전에서만 적용
경로 번복 루프①스위칭 규칙 없음 ②목표가 얇은 벽 너머일 때 플래너 허용 오차로 끝점이 교대 ③마킹 10 m/클리어 12 m 비대칭으로 깜빡임원본은 eband 하나뿐이라 선택 번복이 구조적으로 없었음v0.30 히스테리시스, v0.41 스위칭 기본 꺼짐, v0.48 같은 목표 판정·범위 통일
보행자에 매번 우회 / 팔레트에 다가가 끼임막힘 즉시 재계획(보행자) ↔ 2 m 앞에서야 판단·0.6 m 앞 정지(팔레트)의 양극단원본은 eband가 국소 변형으로 흡수, 정지는 obstacle_stop 10 s 규칙v0.49 대기 → v0.55 4.5 m 선감지·고정/이동 분류·1.2 m 정지
장애물 소멸 후 복귀 불가(유령 셀)무반사 광선이 셀을 지우지 않음원본은 TTL 2 s로 자동 소멸v0.40 inf_is_valid. (TTL 방식이 더 단순·강건 — 실기에서 재검토)
끼인 자세에서 정지회전·전후진 정렬 후보가 모두 닿음, "장애물에서 떨어지기"·미세 동작 후보 없음원본은 저속·넓은 공간 전제라 해당 상황이 드물었음v0.57 back_off, v0.65 미세 정렬·축 방향 후진
속도가 코너 중에 뚝 떨어짐cos(조향) 결합 감속이 회전과 동시에 작동(사전 감속 없음)원본과 동일한 법칙v0.18 경로 기반 속도 프로파일(회피 곡선엔 미반영 — 남은 과제)
요약. 시뮬에서 가장 많은 문제를 만든 것은 두 가지 이식 결정이었다. (1) 홀로노믹 경로까지 0.4 m 기준점으로 추종하게 한 것 — 원본의 직각 주행이 대각선 크랩으로 변질됐고, (2) 안전 계층을 Nav2 collision_monitor로 대체한 것 — 원본의 방향별 차단이 사라져 옆 벽에 멈췄다. 나머지는 Nav2 글로벌 플래너(격자 경로·허용 오차·재계획 주기)와 긴 차체·좁은 통로라는 새 조건이 결합해 생긴 것이다.

3. 이번 수정 (v0.69)

항목내용
홀로노믹 next-point 복원홀로노믹(oblique) 경로에서는 oblique_lookahead(0.10 m, 원본 5 cm) 앞 점을 향해 움직인다. 두 구간 경로(옆→직진, 목표 근처 측면 진입)를 구간별로 주행. 애커만 경로는 기존 0.4 m 기준점 유지(곡선에서 더 부드러움)
직각 회피와의 역할 분담v0.68 직각 회피는 "코앞 장애물·목표는 너머"의 명시적 상황을, 복원된 홀로노믹 법칙은 목표 근처 측면 진입·NEAR 탈출 등 나머지 홀로노믹 경로를 담당

원본 전제이식 환경결과 / 조치

5. 구조 변경 (v0.81): 경로 모양은 정리기, 추종은 컨트롤러

v0.80까지는 플래너 경로의 부자연스러운 부분을 컨트롤러가 주행 중에 하나씩 받아냈다(상황마다 분기 추가). v0.81부터는 경로를 받는 시점에 글로벌 costmap과 실제 footprint로 한 번 정리한다.

단계담당
경로 모양경로 정리기: 출발 평행 이동, 통로 직선화, 경로 밖 준비 지점(목표 축)까지 포함한 주차 접근
경로 추종컨트롤러: 애커만/홀로노믹 법칙, 좁은 구간 방향 유지·옆걸음, 목표 전 정렬 실행
실시간 대응컨트롤러: 대기·고정/이동 분류·조기 우회, 끼임 탈출 / 가드: 방향별 안전

6. 원본에서 아직 가져오지 않은 것 / 남은 과제

항목판단

vcu_filter(조향 정렬 대기·슬립각 히스테리시스)실차 조향 구동부용. MobED CAN 응답을 보고 이식

7. 검증 방법

회귀 러너로 같은 코스를 돌려 숫자로 확인한다: ros2 run midpro_dash run_regression --label v069 --group base,wedge,detour --repeats 3. 특히 side_align(측면 진입)과 bay_exit에서 홀로노믹 구간이 직각으로 움직이는지, w_insert_close·w_pallet_drop에서 직각 회피가 발동하는지를 본다. 장애물 편집 탭의 레이아웃 저장으로 문제 배치를 고정해 두면 수정 전후 비교가 정확하다.
