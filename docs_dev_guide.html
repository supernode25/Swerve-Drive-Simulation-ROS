1. 개요·아키텍처

구조의 핵심은 midpro의 판단·제어 로직을 Nav2 컨트롤러 플러그인 하나에 담고, 경로 생성·복구·안전 감시·인프라는 Nav2 표준 부품을 쓰는 것입니다. 로봇 거동을 결정하는 부분(FSM, 로컬 경로 상태, 코스트 밴드 규칙)은 자체 코드이고, 교체 가능한 부분은 표준 플러그인 자리에 둡니다.

데이터 흐름

실선은 명령·경로의 주 흐름, 점선은 센서·보조 흐름. 컨트롤러 안의 ①②③이 midpro 로직, ④는 이식 때 추가한 부분입니다.

1.3 ROS2 / Nav2 용어와 연동 구조

이 문서에 나오는 ROS2 용어는 네 가지 통신 방식과 두 가지 인프라(TF, 라이프사이클), 그리고 Nav2의 서버·플러그인·BT 구조로 정리됩니다. ROS1 move_base 하나가 하던 일이 ROS2에서는 여러 서버로 나뉘어 액션으로 연결됩니다.

통신 원시 네 가지. 액션은 "오래 걸리고 중간 보고가 필요하며 취소될 수 있는 작업"에 씁니다. 내비게이션의 모든 단계가 액션입니다.

Nav2는 역할별 서버로 나뉘고, bt_navigator만이 다른 서버에 액션을 보냅니다. 각 서버는 "플러그인"(pluginlib로 로드되는 공유 라이브러리)을 품고 있으며 midpro 컨트롤러도 controller_server의 플러그인입니다.

액션 한 번의 흐름. NavigateToPose 안에서 bt_navigator가 다시 FollowPath 액션을 controller_server에 보내므로 액션이 중첩됩니다.

이 워크스페이스의 BT. 제어 흐름 노드(Sequence/Fallback/Recovery/Rate)가 액션·조건 노드를 어떤 순서로 틱할지 정합니다. XML 한 파일이 곧 임무 로직입니다.

모든 Nav2 서버는 라이프사이클 노드입니다. launch의 lifecycle_manager가 순서대로 configure → activate 하며, 플러그인의 같은 이름 함수가 그때 불립니다.

프레임 관계. 시뮬레이터(또는 오도메트리)가 odom→base_link를, 측위가 map→odom을, URDF(robot_state_publisher)가 고정 조인트를 발행합니다.

2. 개념 카탈로그

2.1 제어 상태기계 (FSM) midpro

컨트롤러는 다섯 상태를 갖고, 20 Hz마다 하나의 상태 블록이 cmd_vel을 만듭니다. 전이 조건은 전부 거리·각도 임계값입니다.

ROS1 controlLoop()의 전이를 그대로 옮긴 것. 임계값: approach_dist 0.8 m, dist_tol 0.02 m, yaw_tol 0.025 rad(1.4°), FINAL_APPROACH 확인 5틱.

이론 참고유한 상태 기계 (FSM)

FSM은 5-튜플 M=(Q,Σ,δ,q0,F): 상태 집합 Q, 입력 Σ(거리·각도 조건), 전이 함수 δ:Q×Σ→Q, 초기 상태 IDLE, 종료 상태 IDLE(도착). 출력이 상태에만 의존하면 Moore, 상태+입력이면 Mealy. 이 컨트롤러는 상태별로 cmd_vel을 만들고 전이 조건이 입력이므로 Mealy형입니다.

임계값 하나로 전이하면 경계에서 떨림(chattering)이 생기므로 교재는 히스테리시스(진입 임계 ≠ 해제 임계)를 권합니다: ROTATE 진입 8.6°, 해제 1.4°가 그 예.

이산 수학·디지털 시스템 설계, 로봇소프트웨어 설계(상태 기반 행위 설계)

2.2 로컬 경로 상태 midpro

플래너 틱(10 Hz)마다 현재 목표까지 어떤 경로를 줄지 정합니다. 핵심은 직선 가시선 검사(경로 중심선 셀의 비용이 95 이상이면 막힘)이고, 막힌 정도에 따라 상태가 내려갑니다.

ROS1 LocalPlanner::run(). 원래 detour(eband)는 "최후의 수단"이지만, 먼 목표를 한 번에 주면 직선이 거의 항상 막혀 detour가 주된 경로가 됩니다(§6 참고).

이론 참고가시선 검사와 격자 레이캐스팅

두 점 사이 선분을 격자 해상도 간격으로 표본화해 셀 비용을 읽는 것은 Bresenham/DDA 레이캐스팅의 단순형입니다. 표본 간격이 해상도보다 크면 셀을 건너뛰어 장애물을 놓칠 수 있으므로 간격 ≤ 해상도여야 합니다(현재 res).

pk=p0+kN−1(p1−p0),N=⌈‖p1−p0‖/res⌉

측면·전방 우회점 탐색은 가시성 그래프(visibility graph) 플래닝의 1단계 근사입니다: 후보점에서 목표가 보이면 경로 = 2개 선분.

컴퓨터 그래픽스(레이캐스팅), 로봇공학 경로 계획(가시성 그래프)

2.3 홀로노믹 / 애커만 판정 midpro

플래너가 경로 포즈의 yaw를 채우는 방식이 곧 구동 모드입니다. 고정 yaw(로봇 또는 목표 방향 복사)면 차체 방향을 유지한 채 평행이동하는 홀로노믹, 접선 yaw(다음 점 방향)면 차체가 경로를 따라 도는 애커만입니다. 컨트롤러는 경로의 두 번째·세 번째 포즈 yaw가 같으면 홀로노믹으로 봅니다(ROS1: 1e-10 비교, 이식: 1e-4 rad).

직선 경로는 접선이 모두 같아 홀로노믹으로 판정됩니다. 실제로 애커만이 되는 건 곡선(detour) 경로뿐입니다.

이론 참고홀로노믹 / 비홀로노믹 운동학

구속 조건이 g(q)=0(위치만)이면 홀로노믹, g(q,q˙)=0(속도 포함, 적분 불가)이면 비홀로노믹입니다. 자동차(애커만)의 미끄럼 없음 조건:

x˙sinθ−y˙cosθ=0,θ˙=vLtanδ

(자전거 모델, L 휠베이스, δ 조향각.) 전방향 로봇은 이 구속이 없어 차체 좌표에서 (vx,vy,ω) 세 자유도를 독립으로 냅니다. 스웨브의 바퀴별 속도 벡터:

vi=(vx−ωyi,vy+ωxi),δi=atan2(vi,y,vi,x)

midpro의 "홀로노믹 모드"는 ω≈0으로 차체 방향을 고정하고 (vx,vy)=v(cose,sine)로 분해하는 것, "애커만 모드"는 vy=0에 ω로 방향을 맞추는 것입니다. 바퀴가 재정렬되는 데 걸리는 시간이 조향 지연입니다.

로봇공학(이동 로봇 운동학), 차량 동역학(자전거 모델)

2.4 코스트 밴드 100 / 99 / 95 midpro → 추가 복원

midpro의 C++ costmap은 세 단계 계단 팽창을 썼습니다. 95 밴드(외접 반경 0.54 + 0.05 = 0.59 m)가 핵심인데, 플래너가 경로 중심선을 95 이상에서 막으므로 로봇 중심이 장애물에서 항상 0.59 m 이상 떨어지고, 그 거리면 제자리 회전도 안전합니다. 즉 footprint 충돌 검사를 하지 않고도 밴드 하나로 안전 거리를 보장하는 설계입니다.

회색: Nav2 raw 비용. 파란 점선: 컨트롤러 getCost()가 되돌리는 ROS1 스케일. 0.59 m에서의 raw 비용을 inflation layer에서 직접 계산(computeCost)하므로 팽창 파라미터를 바꿔도 밴드 거리는 유지됩니다. 글로벌 costmap은 robot_radius 0.59로 Smac 2D에도 같은 제약을 줍니다.

이론 참고형상 공간(C-space)과 민코프스키 합, 거리 변환

로봇을 점으로 다루려면 장애물을 로봇 형상만큼 부풀립니다(민코프스키 합 O⊕(−R)). 방향을 무시하면 외접원으로 부풀린 보수적 근사가 되고(midpro 95 밴드), 내접원만 쓰면 낙관적 근사(99 밴드)가 됩니다.

rin=min(W/2,L/2),rcirc=(L/2)2+(W/2)2

팽창 레이어는 유클리드 거리 변환(EDT) d(c)=min‖c−o‖에 감쇠를 적용한 것:

cost(d)=252·exp(−k(d−rin)),d>rin

거리 밴드 복원은 이 식의 역함수로 raw 문턱을 구하는 것과 같습니다: cth=cost(0.59).

로봇공학(C-space, Latombe), 영상처리(거리 변환)

2.5 속도 거버너 추가

midpro에는 상황 인식 감속이 없었고(0.2 m/s 고정) 반응형 감속은 obstacle_detector가 맡았습니다. 0.6 m/s로 올리면서 경로 전방 비용·곡률·정지거리로 상한을 정하는 거버너를 FOLLOW_PATH에 넣었습니다. 상황 상한은 governor_floor(0.4) 아래로 내려가지 않고, 목표 제동만 0까지 갑니다. 활성 사유는 /midpro/speed_limit로 발행됩니다.

curve
1 m 앞까지 경로 방향 변화 > 10° → 0.4
inflation
1.2 m 앞 경로에 비용 ≥ 80(벽 0.65 m 안) → 0.5
near_obstacle
경로에 95 밴드 → 0.4
goal_brake
v ≤ min(d, √(2·0.4·d))
ramp
가속 0.4 m/s² 램프 중
이론 참고정지 거리·횡가속·충돌 시간

등감속 정지 거리와 그 역(허용 속도):

dstop=v22a+vtr⇒vmax(d)=2ad(tr=0)

곡선에서 횡가속 한계: v2κ≤alat⇒v≤alat/κ(κ 곡률). 거버너의 curve 상한은 이 식을 각도 문턱으로 단순화한 것입니다. 충돌 시간 TTC=d/vrel은 상대 속도 기준 제동 판단에 씁니다.

제어공학·차량 동역학(종·횡 가속 한계), 기능안전(반응 시간 포함 정지 거리)

2.6 재계획 정책 Nav2 조정

Nav2 기본 BT는 1 Hz로 무조건 재계획합니다. 격자 탐색은 비용이 같은 경로를 여러 개 갖고 있어 부를 때마다 조금씩 다른 경로가 나오고, FSM은 경로의 앞 지점으로 조향하므로 매초 조향이 튀었습니다. 이식 BT는 경로가 무효(장애물)이거나 goal이 바뀔 때만 재계획합니다(IsPathValid). Hybrid-A* detour도 2 s 주기, 경로 유효 3 s입니다.

이론 참고A* 탐색과 휴리스틱

격자 플래너는 f(n)=g(n)+h(n)가 최소인 노드를 확장합니다(g 누적 비용, h 추정 잔여 비용). h가 실제 비용을 넘지 않으면(허용적) 최적 경로가 보장되고, 일관성(h(n)≤c(n,m)+h(m))이면 노드를 한 번만 확장합니다. 비용이 같은 경로가 여럿이면 타이브레이크 순서에 따라 다른 경로가 나오는데, 이것이 재계획 때 경로가 바뀌는 원인입니다.

Hybrid-A*는 상태를 (x,y,θ)로 확장하고 모션 프리미티브(원호)로 이웃을 만들며, 해석적 확장에 Reeds–Shepp 곡선(전·후진 포함 최단 곡선)을 씁니다.

인공지능(탐색), 로봇공학 경로 계획(Dolgov et al. 2008)

조향은 비례 제어 ω=Kpe입니다. 로봇이 경로에 다가가는 동역학은 근사적으로 e˙=−vKpe꼴이라 유효 루프 이득이 속도에 비례합니다. 0.2 m/s에서 안정하던 이득이 0.6 m/s에서는 3배가 되어 진동한 것이 그 예입니다. 지연 τ(조향 정렬, 필터)가 있으면 위상 여유가 줄어 vKpτ≲1 정도가 안정 조건의 경험칙입니다.

20 Hz 이산 제어(T = 50 ms)에서 틱당 변화 한계 Δ는 가속도 한계 a=Δ/T와 같습니다(0.015/0.05 = 0.3 m/s²). 1차 저역 필터 yk=αuk+(1−α)yk−1의 시정수는 τ≈T(1−α)/α(α=0.3 → 0.12 s).

이론 참고Pure Pursuit·Stanley·MPC 계열

Pure pursuit는 lookahead 거리 L 앞의 점을 지나는 원호를 따르며, 곡률은

κ=2sinαL,ω=vκ

(α = 목표점 방향각). L을 속도에 비례시키면 고속에서 안정합니다(RPP). Stanley는 전륜 위치의 횡오차 e와 방향오차 ψ로 δ=ψ+atan(ke/v). MPC는 유한 구간 비용 J=∑t=0Nℓ(xt,ut)를 모델 제약 아래 최소화해 첫 입력만 적용(receding horizon); MPPI는 이를 샘플링과 소프트맥스 가중평균으로 근사합니다(별도 문서 참조). midpro 법칙은 "기준점 yaw 추종 P제어"로, pure pursuit와 Stanley의 방향오차 항만 가진 형태입니다.

5.2 플래너 교체·추가

글로벌 플래너는 planner_server.planner_plugins에 이름을 추가하고 BT의 planner_id로 고릅니다. 컨트롤러는 글로벌 경로를 setPlan()으로 받을 뿐이라 플래너가 바뀌어도 수정이 없습니다.

planner_server:
  ros__parameters:
    planner_plugins: ["GridBased", "Hybrid"]
    GridBased: {plugin: nav2_smac_planner/SmacPlanner2D, ...}
    Hybrid:    {plugin: nav2_smac_planner/SmacPlannerHybrid, minimum_turning_radius: 0.40, ...}
# BT: <ComputePathToPose goal="{goal}" path="{path}" planner_id="Hybrid"/>
  • 글로벌 경로가 벽에 붙는다 → 글로벌 costmap robot_radius(0.59)와 cost_travel_multiplier(4.0)를 올립니다. Smac 2D는 내접 밴드만 차단하므로 반경이 곧 최소 이격입니다.
  • 코너가 둥글다/각지다 → smoother.w_smooth(0.3). 각지게 하려면 0.1 이하.
  • 먼 목표에서 계획 실패 → max_planning_time(8.0), downsample_costmap: true.
  • Hybrid-A*를 detour 전용으로 쓸 때는 /detour 네임스페이스의 두 번째 planner_server를 그대로 쓰고 detour:=true.

5.3 컨트롤러 법칙 수정

controlTick()의 FOLLOW_PATH 블록이 조향·속도를 정합니다. 새 법칙을 넣을 때는 기존 블록을 지우지 말고 tracking_mode 분기로 추가해 A/B가 가능하게 두세요(lookahead 모드가 그 예).

// midpro_control_loop.cpp
if (ctrl_state_ == "FOLLOW_PATH" && tracking_mode_ == "my_law") {
  // path_[0] = 로봇 pose, path_[ref] = heading_lookahead 앞 기준점, path_.back() = 목표
  // 쓸 수 있는 값: dist_to_goal, next_yaw_diff, yaw_error, is_oblique_
  // 반드시 speedGovernor()로 상한을 받고 cmd를 채운 뒤 아래 공통 필터로 보냅니다
}
  • 출력 필터(LPF, 가속 제한, 최소 각속도, 횡속도 클램프)는 공통이라 법칙 안에서 다시 만들지 않습니다.
  • 상태 전이(approach/rotate)는 상단 블록이 처리합니다. 새 법칙이 회전을 원하면 setCtrlState("ROTATE_IN_PLACE", …)만 호출합니다.
  • 다른 Nav2 컨트롤러(RPP, MPPI)로 바꿔 보려면 FollowPath.plugin만 교체하면 되고, midpro 플러그인은 그대로 남습니다.

5.4 코스트맵 확장

  • 센서 추가(뎁스 카메라 등): obstacle_layer.observation_sources에 PointCloud2 소스를 추가. 컨트롤러는 셀 비용만 보므로 변경 없음.
  • 영역 규칙(감속 구역, 금지 구역): Nav2 costmap_filters(keepout, speed). 속도 필터는 setSpeedLimit()으로 플러그인에 전달되며 이미 구현돼 있습니다(speed_scale_).
  • 밴드 거리 변경: near_obstacle_distance만 바꾸면 됩니다. 단 글로벌 robot_radius와 같은 값으로 맞추세요. 팽창 반경은 그 거리보다 커야 합니다(§4.1 경고 참고).
  • footprint 변경(스웨브 0.67×0.60 등): 세 costmap의 footprint, 글로벌 robot_radius(외접+0.05), near_obstacle_distance, collision_monitor PolygonStop을 함께 수정.

6.5 그래프로 성능 평가하기 (midpro_dash)

ros2 run midpro_dash speed_dash --csv run.csv로 기록하면서 아래 기준으로 봅니다. 같은 goal을 3회 반복해 평균으로 판단하고, 파라미터는 한 번에 하나만 바꿉니다. 순서는 속도 램프 → 코너 감속 → 조향 진동 → 도착 제동입니다.

속도 그래프

보는 것좋은 모양나쁜 모양 → 원인 → 조치
출발 램프상한까지 일정 기울기 직선(0.4 m/s² → 0.6까지 1.5 s)계단·톱니 → 감속 주체가 번갈아 깎음 → /midpro/speed_limit 사유 확인, 중복 제거
순항상한에 평평하게0.4~0.6 오르내림 → 전방 비용이 문턱 근처 → inflation_cost_threshold ↑, speed_lookahead_dist ↑
코너 전2~3 m 전부터 완만히(프로파일 곡선과 겹침)직전 급락 → 프로파일 꺼짐 또는 lateral_acc_limit 과소
세 선 관계컨트롤러 출력 ≈ 최종 cmd ≈ 실제(약간 지연)최종 cmd가 계속 낮음 → collision_monitor. 실제가 못 따라감 → 가속 한계(시뮬 acc_vx, VCU)
목표 제동√(2ad) 곡선처럼 완만히 00.1 근처에서 길게 기어감 → profile_min_speed·approach_dist

가속도·저크

지표양호주의불량
가속 RMS (10 s)< 0.15 m/s²0.15~0.3> 0.3: 명령 떨림 또는 감속 중첩
|a| 최대 (5 s)≤ 설정 한계(0.4~0.5)0.5~0.8> 0.8: 필터를 건너뛴 계단
저크 RMS (10 s)< 1.0 m/s³1~2> 2: 틱마다 상한이 바뀜(사유가 깜빡임)

스파이크 주기가 힌트입니다: 1 s → BT 재계획, 0.5 s → Hybrid 브리지, 0.1 s → costmap 갱신에 따른 거버너 반응.
